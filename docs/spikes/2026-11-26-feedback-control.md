# 피드백 제어 — 이중루프 벅 기준 부족 기능과 결정

- 날짜: 2026-11-26
- 성격: 현황 진단 · 설계 결정
- 기준 시나리오: 벅 컨버터 이중루프 제어(외부 전압 루프 PI → 인덕터 전류 지령 → 내부 전류 루프 PI → 듀티 → PWM)

## 현재 상태 (main `7fd83bb`)

지금 LitzSim은 고정 듀티 개루프 전력단까지 해석한다. 측정값을 듀티로 되돌리는 경로가 없어 단일 루프도 구성할 수 없다.

| 필요한 것 | 현재 | 부족한 점 |
| --- | --- | --- |
| 센서 → 제어 신호 | 전압계·전류계·노드 전압계는 파형만 기록 | 측정값을 제어기 입력으로 내는 센서 |
| 지령 | 없음 | 상수·계단·램프 지령 |
| 연산 블록 | 없음 | 합산, 이득, 리미터, PI(포화·적분 누적 방지·초기값) |
| 변조기 | `pwm`은 주파수·듀티 상수, 듀티는 (0, 1) 상수만 허용 | 듀티 입력 PWM(캐리어) |
| 스위칭 시각 | 고정 듀티라 에지 시각을 미리 알고 그 시각에 스텝을 나눔(`solver.rs` 클록 에지) | 듀티가 바뀌는 에지 처리 |
| 게이트 구동 | NMOS는 게이트–소스에 `pwm`이 직접 연결된 경우만 허용 | 제어기 출력이 스위치를 구동하는 경로 |
| 신호선 | 네트는 전부 전기 노드 | 신호 단자·신호선 구분, 블록 기호·배치, 편집기 [제어] 분류 |
| 과도 시험 | 전원은 직류·사인 전압원뿐 | 부하 계단(시간 제어 스위치), 전류원 |
| 제어 관측 | 없음 | 오차·전류 지령·듀티·적분기 상태 기록 |
| 진단 | 전력 회로 진단만 | 대수 루프, 미연결 신호 단자 |
| 파일 규격 | v1에 제어 개념 없음 | 제어 블록·신호 연결 규격 |
| 분석 | 커서 통계 | 파형 Math(#63), 루프 이득·보드 선도는 이후 |

C++ 1차 MVP의 PFC는 파일의 고정 `control` 블록에 제어기를 하드코딩했고 PWM 주기마다 갱신했다([MVP 검증 기록](../reviews/pfc-validation.md)). 범용 블록 구조가 아니며 v1은 이 필드를 거절한다(`examples/pfc.litzsim`).

## 소유자 결정 (2026-11-26)

1. **센서를 따로 둔다(PSIM 관례).** 전압 센서·전류 센서는 이득을 곱한 신호를 출력한다. 전압계·전류계·노드 전압계는 파형 표시용으로 그대로 둔다. 전류 센서는 도선에 직렬, 전압 센서는 두 단자로 노드에 연결한다.
2. **제어 갱신은 샘플 방식(A)부터.** 샘플 시각에만 제어를 계산하고 한 캐리어 주기 동안 듀티를 고정한다. 에지 시각을 주기 시작에 알 수 있어 현재 해석기의 에지 분할을 그대로 쓴다. 실제 DSP 디지털 제어와 같다. 첫 단계는 주기 시작 1회 갱신만 하고, 꼭짓점·골 2회 갱신과 계산 지연은 이후 선택 항목으로 둔다.
3. **연속 비교(B)는 필요할 때 확장한다.** time-step마다 캐리어와 비교하는 아날로그 제어는 교차 시각 탐색과 한 주기 다중 교차 처리(래치)가 필요하므로 뒤로 미룬다.

4. **제어기는 블록 다이어그램으로 표현한다.** 합산·이득·리미터·PI를 신호선으로 연결한다. 화면과 AI가 같은 편집 연산을 쓰는 현재 구조와 맞는다. 수식·코드 블록은 이후 후보.
5. **적분기 블록을 둔다(PSIM 관례).** 이득과 적분기로 PI를 직접 구성할 수 있어야 한다. 적분기는 PI 블록과 같은 이산화 방식을 쓰고, 같은 계수로 구성한 이득+적분기+합산은 PI 블록과 같은 결과를 내야 한다.

## 검증 원칙

- 결과를 보기 전에 기준을 정한다. 정상상태는 지령 대비 출력 평균 오차, 과도는 평균 모델(같은 제어기·지령·초기조건) 대비 PWM 주기 평균 차이로 본다. PSIM 결과가 있으면 같은 조건에서 비교한다.
- 기존 개루프 예제의 결과는 비트 단위로 불변이어야 한다.

## 미검증 범위

- 연속 비교(B), 다중 샘플률, 계산 지연, 보드 선도는 이 계획에 없다.
