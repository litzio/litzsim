# Rust 재구축

2026-11-26 · 소유자 결정

C++·Qt로 만든 1차 MVP를 보관하고 Rust로 처음부터 다시 쌓는다. 원격으로 직접 써 본 Qt 편집기의 반응과 메뉴가 기대에 못 미쳤고, 웹 화면 전환을 위해 코어를 Qt에서 분리하는 수술이 어차피 필요했다. 엔진 언어는 Rust로 확정한다. 코드보다 값진 것은 무엇을 어떤 조건으로 검증할지 정한 기준이므로, 그 기준을 새 구현의 인수 조건으로 가져간다.

## 보관 위치

- 브랜치 `archive/qt-cpp-mvp`, 태그 `archive/qt-cpp-mvp-2026-11-26` — 재구축 직전 main(PR #29까지). C++ 엔진, Qt 편집기·파형 창, SVG/PDF 내보내기, 예제 회로와 시험이 그대로 있다.
- `spike/24-web-waveform`, `spike/25-litzio-plugin` — 웹 파형 표시와 Litzio 플러그인 시제품.
- 이슈·PR #1–#29의 논의와 검토 기록은 GitHub에 남아 있다.

`docs/mvp.md`, `docs/reviews/`, `docs/spikes/`의 날짜 붙은 문서는 그때의 C++·Qt 구현을 기준으로 쓴 기록이다. 코드 링크는 보관 태그를 가리킨다.

## 새 구현이 다시 통과할 기준

같은 회로·제어·초기조건에서 대조한다. 수치는 보관 구현의 측정값이며, 새 구현은 기준을 먼저 정한 뒤 측정한다.

| 영역 | 기준과 근거 |
| --- | --- |
| RC·RLC 해석 | 5 V 계단, 0–5 ms. time-step을 절반으로 줄일 때 해석해 대비 최대 오차가 거의 절반으로 준다(1차 수렴). [MVP 검증 기록](reviews/pfc-validation.md) |
| 이상 벅 | 연속·불연속 전도의 구간 기준해, 전류 피크, DCM 첫 영전류 시각(기준해 83.33 µs). [MVP 검증 기록](reviews/pfc-validation.md) |

## 유지하는 결정

- 회로의 단자·연결·측정 방향과 편집 연산은 공통 코어가 소유하고 화면과 AI는 같은 연산을 부른다.
- 화면은 웹(React)으로 만든다. 1차 제품은 Litzio 플러그인이며 단독 실행판은 나중으로 미룬다([제품 목적](purpose.md#litzio-플러그인-우선)의 네 경계를 지켜 나중에 넓힐 수 있게 한다).
- 최우선 검증은 Litzio 위에서 시뮬레이터를 막힘없이 쾌적하게 쓸 수 있는가다.

## 다시 정할 것

Rust 기반 아키텍처 설계에서 판정한다.

- Rust 코어를 플러그인에 싣는 방식: WASM, 플러그인에 동봉한 실행 파일(상주 프로세스), Node 네이티브 모듈. Litzio는 플러그인 설치 때 네이티브 빌드를 하지 않는다.
- 단독 앱 껍데기(Electron 또는 Tauri)는 단독 배포를 결정할 때 정한다.
- 빌드된 배포물: 다른 PC에서 빌드 도구 없이 플러그인을 설치해 쓸 수 있게 GitHub Actions로 플러그인 묶음(Windows용 코어 포함)을 만든다(빌드 도구 설치가 막힌 PC에서 1차 MVP를 써 볼 수 없었다).
