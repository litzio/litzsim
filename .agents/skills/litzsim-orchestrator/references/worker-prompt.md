# 작업자 프롬프트

`<...>`만 바꾸고 공통 규칙은 그대로 붙인다. 승인된 결정은 사용자가 확정한 내용만 쓴다. 해결책을 새로 지어내지 않는다. 오케스트레이터가 정한 값(허용오차, 비교 구간, 화면 치수)은 기존 검증 기록이나 지금 화면에서 직접 확인한 것만 확정으로 적고, 글로만 떠올린 것은 "제안, 실행 결과로 확인한 뒤 확정"으로 표시한다.

```text
## 공통 규칙
- AGENTS.md, docs/purpose.md, docs/README.md에서 연결된 관련 문서를 먼저 읽는다.
- 가장 작은 변경으로 해결한다. 무관한 리팩터링과 문서 수정은 하지 않는다. 현재 동작을 바꾸면 README·관련 문서를 같은 PR에서 갱신한다. README에는 실제로 실행하고 확인한 기능만 쓴다.
- 회로의 단자·연결·측정 방향과 편집 연산은 공통 코어(`src/circuit.*` 등 GUI에 의존하지 않는 코드)에 둔다. GUI(`studio`·`schematic`)와 CLI는 같은 연산을 호출한다. 한쪽에만 의미를 구현하지 않는다.
- `*.litzsim` 규격을 바꾸면 `version`, `examples/`, README의 규격 설명, 저장→재열기 시험을 함께 고친다. 승인된 결정 없이 규격을 바꾸지 않는다.
- 문서의 서술이 기존 코드와 다르면, 이번 작업이 바꾸기로 한 것이 아닌 기존 코드를 문서에 맞춰 고쳐 쓰지 않는다. 판정할 수 없으면 기존 코드의 관례를 따르고, 발견한 불일치는 최종 보고에 적는다.
- 기능·파일·식별자를 삭제하거나 이름을 바꾸는 PR은 지운 이름으로 `git grep`한 결과(0건 또는 남긴 곳과 이유)를 PR 본문에 적는다.
- 빌드와 검사: PowerShell에서 `$env:PATH = "C:\msys64\ucrt64\bin;$env:PATH"`를 먼저 하고, `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release`, `cmake --build build`, `ctest --test-dir build --output-on-failure`를 실행한다. 이 worktree의 `build/`만 쓴다. <추가로 실행할 비교 명령. 없으면 이 문장을 지운다>
- 기존 테스트 보완을 우선한다. 고유한 보호 가치가 있는 검사만 추가하고, 새 시험은 `CMakeLists.txt`에 등록한다. GUI 시험은 기존처럼 `QT_QPA_PLATFORM=offscreen`으로 돈다. 시험을 추가하면 기존 시험과 다른 결함, 관측 실행 시간을 PR 본문에 적는다.
- 버그는 수정 전 실패를 먼저 확인한다. 재현할 수 없으면 추측성 수정 없이 근거를 보고한다.
- 수치 기준(허용오차·기준해)은 결과를 보기 전에 정하고, 결과에 맞춰 바꾸지 않는다. 기준이 틀렸다는 근거(해석해 재유도, 독립 계산)가 있을 때만 고치고 그 근거를 PR 본문에 쓴다. 단언 삭제·완화, 재시도, timeout 증가로 실패를 덮지 않는다.
- 해석기·소자 모델을 바꾸면 같은 회로·제어·초기조건에서 전후를 비교하고, 정확도와 실행시간을 비교 조건(CPU, 빌드 종류, 측정에 포함한 범위)과 미검증 범위와 함께 PR 본문과 필요하면 `docs/reviews/pfc-validation.md`에 남긴다. 한 조건의 결과를 모든 운전점으로 일반화하지 않는다.
- 화면이 바뀌면 PR을 올리기 전에 자기 캡처로 단자·측정 방향 표시, 라벨과 기호의 겹침, 파형 축·범례·피크 가독성을 확인한다. 캡처는 실제 Windows 플랫폼의 창 콘텐츠로 찍고, 리치오와 비교하는 변경이면 docs/mvp.md의 화면 변경 검토 기준을 따른다.
- 공개 PR·커밋·이슈·댓글과 커밋하는 캡처에 로컬 경로, Windows 계정 이름, PC 이름, 임시 폴더 위치가 나오지 않게 한다. 이미 push했으면 덮어쓰기 전에 멈추고 부모에게 보고한다.
- 리뷰 agent나 하위 agent를 띄우지 않는다.
- 결정 범위 밖의 판단(해석 결과를 바꾸는 모델 선택, 파일 규격 변경, 단자·측정 방향 규약 변경)이 필요하면 구현을 멈추고 근거와 선택지를 보고한다. 이슈가 추정한 원인이 틀렸으면 범위 밖 구현만 멈추고 승인된 범위의 읽기·재현·판정은 계속한 뒤 보고한다.
- 첫 커밋 전에 `paseo inspect $env:PASEO_AGENT_ID --json`(PowerShell)으로 자신의 실행 provider·model을 확인한다. 확인할 수 없으면 추측하지 말고 부모에게 보고한다.
- 커밋은 UTF-8 메시지 파일(`git commit --file`)로 만든다. 제목과 본문은 한국어로 쓴다. 마지막 trailer 블록에 정확히 `AI-Agent: <agent>`, `AI-Model: <provider>/<model>`을 한 번씩 넣는다(실제 구현 모델, 소문자 canonical id). merge 커밋도 포함한다. Co-authored-by는 쓰지 않는다. 저장소의 이전 커밋 trailer(예: `AI-Model: GPT-6`)를 본뜨지 않는다. 커밋마다 `git log -1 --format='%H%n%(trailers:only)'`로 확인한다.
- main을 base로 PR을 만든다. 본문에 `Closes #<N>`(일부만 해결하면 `Refs #<N>`), 변경 요약, 실행한 검증(명령과 결과, CTest 통과 수)을 쓴다. 재생성 가능한 대용량 결과 파일은 커밋하지 않는다.
- 이 저장소에는 CI가 없다. PR을 올린 뒤 기다릴 검사는 없으며, 병합 전 검증은 오케스트레이터가 따로 한다. 병합은 하지 않는다.
- 주 checkout이나 다른 worktree의 폴더를 가리키는 junction·심볼릭 링크를 만들지 않는다. 만들었으면 끝낼 때 링크 항목만 지우고(재귀 삭제 금지) 보고에 적는다.
- 끝나면 직접 띄운 LitzSim 창과 프로세스를 정리한다. 최종 보고에는 PR URL, head SHA, 변경 요약, 검증 결과, 남은 프로세스 여부, 범위 밖 발견을 포함한다. 한국어 정상 문장으로 보고한다.
- 완료 보고는 최종 답변에 한 번만 작성한다. Paseo의 자동 finish 알림으로 전달되므로 부모에게 `send_agent_prompt`나 CLI 메시지로 같은 완료 보고를 별도 전송하지 않는다. 부모 또는 동료에게 보내는 직접 메시지는 중간 질문·차단 사항·진행에 필요한 인계에만 사용하며, 상대의 `serverId`를 확인한 뒤 `notifyOnFinish: false`로 보낸다. 최종 답변은 그 메시지를 읽지 않아도 결과와 남은 일을 알 수 있게 작성한다.
```

## 후속 지시 예

아래 후속 지시에도 공통 규칙의 완료 전달 방식을 함께 붙인다.

- **main 반영:** "PR #<M>(<무엇을 바꿨는지>)이 main에 병합됐다. origin/main을 merge해 양쪽 의도를 보존하며 충돌을 해결하라. merge 커밋 trailer를 확인하고, Release 빌드와 CTest 전체를 실행한 뒤 push하라. 새 head와 결과를 보고하라. 병합하지 않는다."
- **병합 검증 실패:** "오케스트레이터가 origin/main <sha>와 PR head <sha>를 합친 결과에서 `<시험 이름>`이 `<오류>`로 실패했다. origin/main을 merge해 같은 결과를 재현하고, 이 PR의 문제인지 앞서 병합된 PR <#M>과의 상호작용인지 판정한 뒤 고쳐라. (공통 규칙의 판정 기준을 적용) push 후 원인, 수정, 새 head를 보고하라."
- **병합 검증 대행(완료 알림이 오는 백그라운드 실행이 없는 하네스):** "`node .agents/skills/litzsim-orchestrator/scripts/pr-verify.mjs --pr <N>`을 실행하고 마지막 `로컬 검증:` 줄 또는 실패한 단계와 오류를 그대로 보고하라. 수정은 하지 않는다."
- **리뷰 중 대기:** "같은 worktree에서 독립 리뷰어가 `build-review/`로 검토한다. 리뷰가 끝날 때까지 수정·push하지 마라."
- **재개:** "모델 오류로 턴이 중단됐다. `git status`, `git log --oneline -3`, 열린 PR을 확인한 뒤 처음 지시대로 이어서 진행하라. 끝낸 단계는 반복하지 마라."
